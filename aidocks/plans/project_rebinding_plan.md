- Now: the settings menu's Keyboard tab opens rebind_keyboard_action() (menus/bindings_menu.nvgt: add, edit, remove; F1 and the Keyboard tab's view are view_keyboard_bindings()). Add and edit capture with kc_capture_combo() in deps/key_config.nvgt: an audio_form keyboard area runs form.monitor() and takes the first non-modifier key from keys_pressed(), prefixing LSHIFT+, LCTRL+ or LALT+ if either side is held (always the left name), then kc_choose_trigger() (press, repeat, down, release). Tab and Shift+Tab are the form's own focus keys, so they never reach the capture. keyboard.ini can hold side-agnostic SHIFT, CTRL and ALT (heartbeat_up=SHIFT+HOME:repeat), which _kc_expand_modifiers() turns into LSHIFT and RSHIFT bindings on load; but get_keyboard_action_string(), used to save (kc_save_preserving()) and by the two screens, writes each stored variant out, so one save turns SHIFT+HOME:repeat into LSHIFT+HOME:repeat,RSHIFT+HOME:repeat, and every press binding gains :press.
