Q&A log:
- Q (the dev's, 2026-11-06, after committing the finished stat set): "Should achievements track positive stats only, or both positive and neggitive stats. What do you think? This question applies to what they will say in text." Claude's answer: mostly positive (steps, top speed, obstacles got past, doors opened, items used); negative stats (hits, damage, lives lost, hazard falls) only as a few lifetime milestones, worded lightly as consolation rather than goals (such as falling into 100 hazards over all your runs), never as session achievements, since a run-based "take 500 damage" or "lose 3 lives" rewards dying on purpose and can be farmed in seconds. Awaiting the dev's choice.
- Checked (read only, 2026-11-06): CookieCraze's achievements.table holds many negative ladders (blackjack, dice, slot, roulette, lottery, double or nothing and higher or lower losses, combos broken), all lifetime counts climbing 1, 5, 10 ... thousands, worded as jokes or consolation ("Dealer Pension Fund: Lose 5000 hands of blackjack. Confirmed: CookieCraze's quests.table (up to 5 active at once, coin rewards by rank, rerolls, endless ones returning higher after a prestige) has no losses at all. So in CookieCraze, achievements mix positive and negative, and quests are positive only. Stride Rush has no quests planned; the question of negative achievements is still open.
- A (dev, 2026-11-06): "As for your question, I'd pick option 2 like you recommended." SETTLED: achievements are mostly positive (what you did well); negative stats (hits, damage taken, lives lost, hazard falls) appear only as a few lifetime ladders, worded lightly as jokes or consolation, as CookieCraze's loss ladders are; never as session (single run) achievements, so dying on purpose earns nothing.
- Q: The style. Claude's proposal, CookieCraze's text-based achievements: each one a line in a data file (category, id, the stat it reads, its threshold, whether it's for one run or all runs, whether it's hidden, its name, its description with %threshold%, and a hint), so a new achievement is a new line and no code; ladders of the same stat at rising thresholds, each with its own name and wording; versus ToyMania's generated number tiers (one tracker per stat whose thresholds grow by a formula, worded "Tier 3 of ..."). (Asked 2026-11-06; Claude recommended CookieCraze's.)
- A (dev, 2026-11-06): "I was thinking of an ini and or json file for them, in data/config. So no harcoded text if possible." SETTLED: data-driven, CookieCraze's idea (one entry per achievement, ladders as separate entries with their own names), but in a file in sdr/data/config, with no achievement text in the code. Checked: the game already reads ini through deps/ini.nvgt (keyboard.ini, key_config), and the legacy engine also parses JSON (Poco, json_parse() in pocostuff.cpp).
- Q: ini or JSON? Claude's proposal: ini, data/config/achievements.ini, one [section] per achievement with plain key=value lines (category, stat, threshold, scope run or lifetime, hidden, name, description with %threshold%, hint): the game already reads ini the same way for keyboard.ini; it's the easiest to edit by hand, since a typo spoils one line, while one missing comma or quote in JSON stops the whole file loading. JSON would suit nested data, which achievements don't need. (Asked 2026-11-06; Claude recommended ini.)
- EXAMPLE written (dev, 2026-11-06: "Give me an ini example. It's better if you write it in achievements.ini in data/config"): sdr/data/config/achievements.ini, not read by the game yet: a comment header naming each key (category, stat, threshold, scope run or lifetime, hidden, name, description with %threshold%, hint) and noting that deps/ini.nvgt treats a semicolon as a comment, so achievement text can't use one; seven sample entries: a lifetime steps ladder (first_steps 1000, long_haul 10000, marathon 100000), door_to_door (3 real doors in one run), glazier (50 walls, lifetime), spot_the_fake (5 fake doors in one run, hidden) and gravity_wins (100 hazard falls, lifetime, the light negative kind, category mishaps).
